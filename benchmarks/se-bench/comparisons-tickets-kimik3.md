**Verdict: tower (slight)** — Both are clean, dependency-free single-module stores passing all acceptance tests, but tower pairs a stricter validate-then-mutate update path with a materially broader regression suite (full transition matrix, update atomicity, nextId repair, durability per mutation) and a more precise README. pi has the better encapsulation instinct — deep-cloned returns, unique temp files, wrapped corrupt-file errors — yet ships an unguarded partial-mutation path in update() that its own tests never exercise, while tower's main flaw (leaking live references) requires caller misuse and is at least consistently tested around.

Key difference: tower proves state integrity with tests (validate-before-mutate plus an explicit no-partial-update assertion), whereas pi's update() applies fields one at a time before finishing validation, so a rejected multi-field update silently alters in-memory state that the next save persists — and pi's suite would never catch it.
